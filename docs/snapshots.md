# Snapshots

Every SingleFile capture in `Instagram_snapshots/`, and what each one is evidence *for*. Read this when you need to pick the snapshot that exercises a rule you are about to change.

**The folder is untracked**, because every capture is of a logged-in session. A fresh clone has no snapshots, so neither `verify.py` nor `scoped.py` can run until they are captured locally. `.gitignore` gives the reason.

Both scripts read this folder and nothing else — `verify.py` sets `SNAPSHOTS`, `scoped.py` imports it. `verify.py` loads exactly one feed page: `find_snapshot()` takes the newest `Instagram_feed*.html`, so a fresh capture is picked up without editing anything, and nothing it reports covers the post, reel or modal pages. `scoped.py --diff` is the one that reads all of them, each at the URL in the `url:` comment SingleFile writes at the top.

What a snapshot can and cannot prove is in `CLAUDE.md`; it is a short section and it matters before you trust a count measured here.

**The folder was re-captured on 2026-09-17 and now holds 19 files, not the 21-22 that earlier counts in `CHANGELOG.md` and the rule notes were measured against.** Those counts are records of the corpus as it stood on the day and are left as written; do not read them as describing the folder today. Ten of the current nineteen carry Instagram's new `x1ykew4q` wrapper class -- `Instagram-p-id(carousel133)`, `Instagram-p-id(carousel75)`, `Instagram-p-id(single_photo100)`, `Instagram-user-p-id(carousel56)`, `Instagram-user-p-id(single_photo133)`, `Instagram-user-p-id(single_photo56)`, `Instagram-user-p-id(single_photo75)`, `Instagram-user-reel-id(reel125)`, `Instagram-user-reel-id(reel177)` and `Instagram-user-reel-id(reel75)` -- and the other nine do not. That split is a `grep` over the saved HTML, not a rendered measurement. **A row's pixel measurements predate the re-capture unless the row says otherwise**, so a row describing a file that now carries `x1ykew4q` is describing the page as it was before Instagram's change.

| `Instagram-p-id-modal(single_photo).html` | The **same post as that one**, captured as the floating modal opened over a profile grid. Its URL is the plain `/p/<id>/` permalink, so the `regexp()` block selects it — but no rule in either reaches it, so only the `domain()` block does. Two separate guards do that work, and both were measured here: `main div[style*="--x-maxWidth"]` matches 0 (the page's one `--x-maxWidth` element is inside the dialog, not under `main`, and carries `inherit` rather than a width), and `main > div > div.xvc5jky` matches 0 — **`.xvc5jky` itself matches 5**, all inside the dialog, so it is the `main > div > div` child chain and not the class that keeps the carousel and single-photo rules off. Loosen that chain to a descendant combinator and every one of them fires on the modal. It is the one saved page with an `<article>` **inside** a `[role="dialog"]`, which makes it the test for the modal guards. |
